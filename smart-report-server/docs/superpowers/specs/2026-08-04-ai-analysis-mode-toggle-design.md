# AI 分析双模式开关 + 用户补充提示设计

日期：2026-08-04
状态：已获用户批准

## 背景

支持包整包分析上线后，AI 智能分析同时服务两类输入：单一文本日志与支持包压缩包。用户要求显式区分两种模式，并提供给 AI 补充提示的入口。

## 已定决策（用户在对话中确认）

- 默认**单文件模式**：只分析文本类单一日志文件（txt/log/csv/json/xlsx 等）。
- 开关切换至**支持包模式**：上传压缩包，后台自动拆包分析（复用 archiveAnalysisService）。
- 新增**补充提示文本框**：用户可给 AI 方向性提示（如「已确认硬盘故障，重点检查存储」）。

## 组件

### 1. 前端 AIAnalysisPanel

- `mode: 'file' | 'archive'` 状态，默认 `'file'`；顶部模式切换开关（单文件模式 ⇄ 支持包模式）
- 文件类型与模式不匹配时**自动切换模式** + toast 提示：
  - 单文件模式下传压缩包 → 切到 archive，保存当前类别到 `prevCategoryRef`，类别自动设为 `support`
  - 支持包模式下传普通文件 → 切回 file，类别恢复 prevCategoryRef（缺省 host）
- 手动切换模式时执行同样的类别保存/恢复；若已选文件与新模式不匹配则清空已选文件
- 上传区 accept 属性与提示文案随模式变化
- 「补充提示（可选）」可折叠文本框（两种模式都显示），占位符：`已确认硬盘故障，请重点检查存储子系统`；内容随表单 `userHint` 字段上传

### 2. 后端 analyze-file（routes/ai.ts）

- 读取 `req.body.userHint`（字符串，截断至 2000 字符）
- 在 `getPrompt(...)` 生成的提示词后追加：
  `\n\n## 用户补充提示\n用户提供了以下背景信息，请在分析时重点关注：\n<hint>`
- 其余逻辑（压缩包检测、类别校验、流式分析）不变

## 错误处理

- userHint 非字符串或超长：静默截断，不报错
- 模式与文件不匹配：前端自动纠正，无需后端校验（后端仍按内容 magic bytes 检测压缩包，兜底一致）

- 双端 tsc + 前端 vite build
