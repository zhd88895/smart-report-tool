## 第1章 项目简介

### 1.1 项目概述

智能报告生成工具（Smart Report Tool）是一款面向 **IT 运维团队**的自动化巡检报告生成平台。系统采用前后端分离架构，前端基于 React 18 + Vite 5 构建现代化单页应用，后端基于 Express + TypeScript 提供 RESTful API 服务，数据存储采用轻量级 SQLite 数据库。

系统的核心能力是：**上传巡检脚本 → 批量导入巡检数据 → 后端真实执行脚本 → 自动识别并输出格式化报告**。通过脚本化、模板化和 AI 辅助，将传统手动报告编制时间大幅缩短，同时提供可视化操作界面，使非技术人员也能独立完成专业巡检报告的生成。

### 1.2 产品目标

本系统致力于实现以下三大核心目标：

1. **提升运维巡检效率**：通过脚本化执行、模板化输出和 AI 辅助分析，将传统手动报告编制时间缩短 70% 以上。
2. **降低报告生成门槛**：提供可视化的四步向导流程（日志上传 → 填写信息 → 模板选择 → 提交生成），即使非技术人员也能独立完成专业巡检报告。
3. **构建可检索的知识资产**：历史报告与 AI 对话记录结构化沉淀，支持自然语言检索与智能分析，帮助团队积累运维经验。

### 1.3 核心能力

本系统提供以下核心功能：

| 功能模块 | 说明 |
|----------|------|
| **巡检脚本管理** | 上传、分类、搜索、下载、删除巡检脚本，支持 Python/BAT/PowerShell/Shell 等多种脚本类型 |
| **报告模板管理** | 内置多种报告模板，支持用户自定义上传模板（docx/xlsx/md/pdf） |
| **文件上传与处理** | 支持巡检数据文件批量上传，支持压缩包自动解压 |
| **脚本真实执行** | 后端通过 `child_process.spawn` 真实执行用户上传的脚本，非模拟 |
| **实时日志推送** | 通过 SSE（Server-Sent Events）实时推送脚本执行日志到前端 |
| **报告生成与下载** | 脚本输出 + 模板套用自动生成报告，支持多种格式下载 |
| **AI 智能助手** | 嵌入式多轮对话，支持巡检报告智能分析、自然语言检索历史报告 |
| **AI 代码分析** | 支持 AI 代码分析、网页访问、知识库检索等高级能力 |
| **用户与权限管理** | 多角色权限控制（管理员/高级用户/普通用户），支持用户 CRUD |
| **内嵌 Python 环境** | 支持 Python 3.6-3.14 多版本管理，使用 virtualenv 隔离依赖 |

### 1.4 适用场景

本系统适用于以下典型运维场景：

- **定期巡检报告生成**：将日常巡检脚本上传至平台，每次巡检时只需上传数据文件即可自动生成格式统一的报告。
- **批量数据分析**：批量上传多台设备的巡检数据，通过脚本批量处理并生成汇总报告。
- **历史报告检索**：通过 AI 助手以自然语言方式检索历史报告，快速定位特定时间段或特定设备的巡检记录。
- **运维知识沉淀**：将巡检经验通过脚本和模板固化，降低团队人员变动对运维质量的影响。
- **数据库性能分析**：上传数据库性能日志，调用 AI Agent 进行智能分析，快速定位性能瓶颈。

## 第3章 安装步骤

### 3.1 获取源代码

```bash
# 方式一：使用 Git 克隆
git clone <仓库地址> 智能报告生成工具
cd 智能报告生成工具

# 方式二：直接下载解压源码压缩包
# 解压后进入项目根目录
cd 智能报告生成工具
```

### 3.2 安装前端依赖

```bash
# 进入前端目录
cd smart-report-tool

# 安装依赖
npm install

# 返回项目根目录
cd ..
```

### 3.3 安装后端依赖

```bash
# 进入后端目录
cd smart-report-server

# 安装依赖
npm install

# 返回项目根目录
cd ..
```

### 3.4 安装根目录依赖（可选）

根目录的 `package.json` 提供了 `concurrently` 工具，用于同时启动前后端：

```bash
# 在项目根目录
npm install
```

### 3.5 配置环境变量

```bash
# 检查后端配置文件是否存在
# 如果不存在，从示例文件复制
cd smart-report-server
cp .env.example .env
```

> ⚠️ **重要**：必须编辑 `.env` 文件，将 `JWT_SECRET` 修改为一个安全的随机字符串。详见[第4章 配置说明](#第4章-配置说明)。

### 3.6 验证安装

安装完成后，目录结构应如下所示：

```
智能报告生成工具/
├── smart-report-tool/          # 前端（含 node_modules/）
├── smart-report-server/        # 后端（含 node_modules/ 和 .env）
├── node_modules/               # 根目录依赖（可选）
├── package.json                # 根目录配置
├── start.ps1                   # Windows 启动脚本
├── start.bat                   # Windows 批处理启动脚本
```

## 第4章 配置说明

### 4.1 后端环境变量配置

后端配置文件位于 `smart-report-server/.env`。以下是所有配置项的说明：

#### 4.1.1 必填配置

| 配置项 | 说明 | 默认值 | 备注 |
|--------|------|--------|------|
| `JWT_SECRET` | JWT 签名密钥 | 无（必须设置） | 用于会话加密，请设置为安全的随机字符串 |

#### 4.1.2 服务配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `PORT` | 后端服务端口 | `3001` |
| `DATA_DIR` | 数据存储目录 | `./data`（相对于后端目录） |
| `ALLOWED_ORIGINS` | CORS 允许的前端来源 | `http://localhost:5173,http://localhost:3000` |
| `NODE_ENV` | 运行环境 | `development` |

#### 4.1.3 安全配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `BCRYPT_ROUNDS` | 密码加密轮数（4-31） | `12` |
| `JWT_EXPIRES_IN` | JWT Token 过期时间 | `24h` |
| `SESSION_EXPIRY_MINUTES` | 会话空闲超时时间（分钟） | `30` |
| `REMEMBER_ME_DAYS` | "记住我"功能有效天数 | `7` |

#### 4.1.4 日志配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `LOG_MAX_SIZE` | 单个日志文件最大大小（字节） | `10485760`（10MB） |
| `LOG_MAX_FILES` | 保留的日志文件数量 | `10` |
| `LOG_FORMAT` | 日志输出格式 | `text`（可选 `json`） |

#### 4.1.5 Python 配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `PYTHON_PIP_INDEX_URL` | PyPI 镜像源 URL | `https://pypi.tuna.tsinghua.edu.cn/simple`（清华镜像） |

#### 4.1.6 AI 模型配置

> **自 2026-07 多厂商 AI 改造起，AI 模型配置已迁移到网页端「系统设置 → AI 设置」页面**，按用户隔离存储在后端数据库中，支持小米 MiMo、DeepSeek、Kimi、通义千问、智谱 GLM、MiniMax、零一万物、OpenAI 及自定义 OpenAI 兼容厂商，支持多模型、默认模型、连接测试、远端模型列表拉取、模型级参数（温度/最大输入输出 Token）与用量统计。以下 `.env` 配置仅作为**系统级兜底**：当某用户未配置任何启用模型且 `MIMO_API_KEY` 有效时，该用户的 AI 调用临时使用此兜底配置（界面会显示「正在使用系统默认配置」提示条）。

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `MIMO_API_KEY` | 系统兜底 AI API Key | 空（不启用兜底） |
| `MIMO_BASE_URL` | 系统兜底 AI API 地址 | `https://token-plan-cn.xiaomimimo.com/v1` |
| `MIMO_MODEL` | 系统兜底 AI 模型名称 | `mimo-v2.5-pro` |
| `MIMO_MAX_TOKENS` | 系统兜底最大输出 token 数 | `4096` |

```env

# Python PyPI镜像（国内加速）
```

## 第5章 启动与运行

### 5.1 一键启动（推荐）

系统提供了跨平台的一键启动脚本，自动完成依赖检查、环境配置和服务启动。

#### Windows 用户

**方式一：PowerShell（推荐）**

```powershell
.\start.ps1
```

**方式二：批处理**

```batch
start.bat
```

> 如果 PowerShell 提示执行策略限制，先运行：
> ```powershell
> Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
> ```

#### Linux/Mac 用户

```bash
chmod +x start.sh
./start.sh
```

#### 一键启动脚本的功能

启动脚本会自动执行以下操作：

1. ✅ 检查 Node.js 是否已安装
2. ✅ 检查并自动安装前端和后端的 npm 依赖
3. ✅ 检查并自动创建 `.env` 配置文件
4. ✅ 检测端口占用（3001 和 5173）
5. ✅ 同时启动前端和后端服务
6. ✅ 实时输出彩色日志

启动成功后会显示：

```
====================================================
        Smart Report Tool v0.4.0
====================================================
  Backend:   http://localhost:3001
  Frontend:  http://localhost:5173
  Health:    http://localhost:3001/api/health
====================================================
  Press Ctrl+C to stop all services
====================================================
```

## 第7章 功能模块说明

### 7.1 用户认证模块

#### 7.1.1 登录

- 访问 http://localhost:5173 进入登录页面
- 输入用户名和密码，点击"登录"
- 支持"记住我"功能，勾选后会话有效期延长至 7 天
- 登录成功后自动跳转到仪表盘页面

#### 7.1.2 安全机制

- **HttpOnly Cookie**：会话标识存储在 HttpOnly Cookie 中，防止 XSS 攻击
- **空闲超时**：30 分钟无操作自动登出（可在配置文件中调整）
- **速率限制**：登录接口每分钟最多 5 次请求，防止暴力破解
- **密码加密**：使用 bcrypt 算法加密存储密码

#### 7.1.3 注册

- 管理员可在用户管理页面创建新用户
- 部分配置下支持自助注册（需管理员开启）

### 7.2 脚本管理模块

#### 7.2.1 功能概述

脚本管理模块用于管理巡检脚本，支持以下操作：

- **上传脚本**：支持 Python (.py)、BAT (.bat)、PowerShell (.ps1)、Shell (.sh) 脚本
- **分类管理**：按五类分类——主机、存储、数据库、虚拟化、网络
- **搜索筛选**：支持按名称关键词搜索、按分类筛选
- **下载脚本**：下载已上传的脚本文件
- **删除脚本**：删除不再需要的脚本

#### 7.2.2 脚本上传流程

1. 进入"脚本管理"页面
2. 点击"上传脚本"按钮
3. 选择脚本文件（支持多文件上传，包含主脚本和辅助文件）
4. 填写脚本名称、选择分类
5. 点击"确认上传"

#### 7.2.3 Python 版本管理

系统内置 Python 多版本管理功能：

- 支持 Python 3.6 ~ 3.14 多个版本
- 使用内嵌 Python（embeddable package），不污染系统环境
- 使用 virtualenv 创建隔离的虚拟环境
- 可在"Python 版本管理"页面查看、下载、切换 Python 版本
- PyPI 镜像默认使用清华源，下载速度更快

### 7.3 报告生成模块

#### 7.3.1 四步向导流程

报告生成采用可视化的四步向导：

**步骤一：日志上传**
- 页面顶部显示五类日志类型标签页：主机 / 存储 / 数据库 / 虚拟化 / 网络
- 切换标签页后，动态展示对应类型的上传区域
- 支持点击选择文件和拖拽上传
- 支持压缩包上传（自动解压）
- 数据库类型额外支持"调用 AI Agent 分析"可选开关

**步骤二：填写报告信息**
- 用户名称：自动填充当前登录用户，不可编辑
- 报告名称：必填，2-100 字符
- 报告日期：默认当前时间，允许修改
- 作者：自动填充当前登录用户

**步骤三：模板选择与预览**
- 展示内置模板网格卡片
- 点击模板卡片即选中（高亮显示）
- 支持自定义模板上传

**步骤四：提交生成并查看进度**
- 汇总展示前三步信息
- 点击"提交生成"后显示进度条
- 通过 SSE 实时推送执行日志
- 生成完成后可下载报告

#### 7.3.2 脚本执行流程

1. 前端上传巡检文件 → 后端存储到 `uploads/`
2. 前端选择脚本和模板 → 发送生成请求
3. 后端创建临时工作目录 `reports/{reportId}/`
4. 后端将脚本、辅助文件、模板复制到工作目录
5. 后端将巡检文件映射到工作目录的 `input/` 子目录
6. 后端根据脚本类型选择执行命令：`python` / `bash` / `powershell` 等
7. 后端通过 SSE 实时推送执行日志到前端
8. 脚本执行完成后，后端根据输出格式生成报告文件
9. 前端下载生成的报告文件

## 第8章 常见问题

### Q1: 端口被占用怎么办？

**现象**：启动时提示端口 3001 或 5173 已被占用。

**解决方案**：

```batch
# Windows - 使用停止脚本
stop.bat

# Windows - 手动查找并终止进程
netstat -ano | findstr :3001
taskkill /PID <进程ID> /F

netstat -ano | findstr :5173
taskkill /PID <进程ID> /F
```

```bash
# Linux/Mac - 查找并终止进程
lsof -i :3001
kill -9 <进程ID>

lsof -i :5173
kill -9 <进程ID>
```

### Q2: 依赖安装失败怎么办？

**现象**：`npm install` 报错或超时。

**解决方案**：

```bash
# 1. 清除 npm 缓存
npm cache clean --force

# 2. 使用国内镜像源
npm config set registry https://registry.npmmirror.com

# 3. 重新安装
cd smart-report-tool && npm install
cd smart-report-server && npm install

# 4. 如果仍然失败，删除 node_modules 后重试
rm -rf node_modules
npm install
```

### Q3: 忘记管理员密码怎么办？

**解决方案**：

1. 停止后端服务
2. 使用 SQLite 工具直接修改数据库中的密码：

```bash
# 进入后端数据目录
cd smart-report-server/data

# 使用 sqlite3 命令行工具
sqlite3 smart-report.db

# 查看用户
SELECT id, username, role FROM users;

# 重置密码（需要使用 bcrypt 加密，建议通过代码重置）
```

或者删除数据库文件重新初始化（会丢失所有数据）：

```bash
# 删除数据库
rm smart-report-server/data/smart-report.db

# 重启服务，系统会自动创建新的数据库和默认管理员
```

### Q4: Python 脚本执行失败怎么办？

**现象**：报告生成时 Python 脚本报错。

**解决方案**：

1. **检查 Python 版本**：在"Python 版本管理"页面确认所需版本已安装
2. **检查依赖包**：确保脚本所需的第三方包已安装到虚拟环境中
3. **查看执行日志**：在报告生成页面查看实时日志输出，定位具体错误
4. **手动测试脚本**：在本地终端手动执行脚本，确认脚本本身无语法错误

### Q5: AI 助手不响应怎么办？

**现象**：AI 助手发送消息后无回复。

**解决方案**：

1. **检查 AI 配置**：进入"设置"页面，确认 AI 模型的 API Key 已正确配置
2. **检查网络**：确认服务器可以访问 AI 模型的 API 地址
3. **更换模型**：尝试切换到其他 AI 模型厂商
4. **查看后端日志**：检查 `smart-report-server/data/logs/` 目录下的日志文件

### Q6: 数据目录在哪里？

**默认位置**：`smart-report-server/data/`

可通过修改 `.env` 文件中的 `DATA_DIR` 配置更改。支持绝对路径和相对路径（相对于后端目录）。

### Q7: 如何迁移项目到新服务器？

**步骤**：

1. 复制整个项目目录到新服务器
2. 确保保留以下关键目录和文件：
   - `smart-report-server/data/`（所有运行时数据）
   - `smart-report-server/.env`（配置文件）
3. 在新服务器重新安装依赖：
   ```bash
   cd smart-report-tool && npm install
   cd smart-report-server && npm install
   ```
4. 启动服务

### Q8: 报告生成后文件在哪里？

**位置**：`smart-report-server/data/reports/{reportId}/`

每个报告有独立的目录，包含：
- 脚本执行的输出文件
- 生成的报告文件
- 相关日志

也可以通过前端"报告下载"页面直接下载。

### Q9: 如何配置 HTTPS？

**推荐方案**：使用 Nginx 反向代理 + Let's Encrypt 证书。

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    # 前端静态文件
    location / {
        root /path/to/smart-report-tool/dist;
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 代理
    location /api {
        proxy_pass http://localhost:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### Q10: 如何备份数据？

**需要备份的内容**：

1. `smart-report-server/data/` — 整个数据目录（含数据库、脚本、模板、报告）
2. `smart-report-server/.env` — 配置文件

**备份命令**：

```bash
# Linux/Mac
tar -czf backup-$(date +%Y%m%d).tar.gz smart-report-server/data smart-report-server/.env

# Windows PowerShell
Compress-Archive -Path smart-report-server\data, smart-report-server\.env -DestinationPath "backup-$(Get-Date -Format 'yyyyMMdd').zip"
```
